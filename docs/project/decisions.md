# Decisions

Append-only decision log. Each row: what was decided, why, how reversible it is, and
who decided. See [`fsamuels/sdlc-standards`](https://github.com/fsamuels/sdlc-standards)
for the format this table follows.

| ID | Date | Decision | Rationale | Reversibility | Decided by |
| --- | --- | --- | --- | --- | --- |
| D-1 | 2026-09-14 | Adopt `fsamuels/sdlc-standards` full layer (standards + skills) | Keep branch naming, docs organization, and PR process consistent with other projects on the same account from day one, rather than drifting and reconciling later | Easy — two `.claude/settings.json` keys plus a few vendored files | fsamuels |
| D-2 | 2026-09-14 | Choose Godot 4 as the engine | Fast iteration and low motivation-risk outweigh Unreal's higher photorealism ceiling, which this project isn't targeting anyway (see README non-goals); Godot's plain-text project files are also the only one of the three a Claude Code cloud session can meaningfully edit | Moderate — asset/logic work invested in Godot won't carry over automatically, though 3D assets (glTF/FBX, PBR textures) port to another engine if needed later | fsamuels |
| D-3 | 2026-09-14 | Start Phase 2 layout blockout before drone capture, using a provisional square boundary sized to the confirmed 24.06-acre parcel total and a placeholder building box, rather than waiting on real GIS/orthomosaic data | Makes visible progress possible while capture is pending; county GIS/parcel viewers are interactive-only and not fetchable headlessly, so exact boundary shape and building footprints aren't available yet | Easy — boundary mesh and building position are explicitly placeholder and get replaced wholesale once real data lands | fsamuels |
| D-4 | 2026-09-14 | Pull the real parcel boundary from the WA State Geospatial Open Data Portal's public `Current_Parcels` ArcGIS `FeatureServer`, queried directly by parcel ID, instead of exporting from the county's own GIS viewer | The county GIS viewer and property search site are JS-driven Esri apps with no visible download option; the state portal republishes the same county assessor parcel data through a public REST endpoint that returns GeoJSON directly, headlessly, superseding the "interactive-only" constraint noted in D-3 | Easy — a GeoJSON file with a documented query, no dependency introduced | fsamuels |
| D-5 | 2026-09-14 | Approximate building footprints from Overture Maps' ML-derived buildings dataset (public S3, queried via DuckDB) rather than tracing them by hand from satellite imagery, since no surveyed county building-footprint layer covers this parcel | Manual tracing from Google Maps/satellite imagery is slow and error-prone; Overture's dataset gives real polygon shapes and rough heights headlessly, at the cost of being an ML approximation rather than surveyed data | Easy — clearly labeled as approximate in `docs/parcel-data.md`; wholesale replacement once real/orthomosaic data lands, same as the D-3 placeholder building box | fsamuels |
| D-6 | 2026-09-14 | Replace the D-3 provisional square boundary and single placeholder building with the real boundary/building data (D-4, D-5) directly in `main.tscn`, using an equirectangular lon/lat→meters projection centered on the parcel's area centroid as the scene's local origin, and unit-sized `BoxMesh`/`BoxShape3D` sub-resources scaled per-node (rather than a distinct sized sub-resource per fence segment/building) | Keeps the .tscn small (13 fence segments + 7 buildings share 2 unit meshes total) instead of ~20 near-duplicate sized sub-resources; equirectangular projection is simple and sufficiently accurate at this scale (a ~450m-wide parcel) versus a full geodesic/UTM projection | Moderate — coordinate origin and axis convention (`+X`=east, `+Z`=south) are now a scene-wide assumption; any future real-world-data import (orthomosaic, drone terrain) needs to reuse the same convention or everything needs re-deriving | fsamuels |
| D-7 | 2026-09-14 | Texture the ground plane with public NAIP aerial imagery (USGS National Map `USGSNAIPPlus` ImageServer, queried headlessly for the same bbox as the ground plane's real-world extent) instead of the flat placeholder color, and store the fetched PNG under `project/textures/ground/` rather than `assets/orthomosaic/` | Free, public-domain, ~0.6–1m resolution imagery gives the case map a real-looking ground texture (roads, tree lines, structures roughly in place) while drone capture is pending, same "pull what's headlessly available now, replace wholesale later" pattern as D-4/D-5; `assets/` isn't reachable from Godot's `res://` root, so the texture the scene loads has to live inside `project/` | Easy — one PNG plus a texture reference in `main.tscn`; swapped out wholesale once the drone-derived orthomosaic (D-3's eventual replacement) is ready, same as the boundary/building placeholders | fsamuels |
| D-8 | 2026-09-14 | Extract the player, fence segment, and building out of `main.tscn` into their own reusable scenes (`player.tscn`, `fence_segment.tscn`, `building.tscn`), instanced into `main.tscn` with only a per-instance `transform` override, instead of each of the 20 fence/building copies carrying its own full node subtree inline | `main.tscn` was on track to grow linearly (~10-12 lines per object) through every future addition (Phase 4-6: vegetation, animals, more buildings), making the file increasingly slow to work with and diff-noisy; instancing means future additions are one node block each, and each shared scene can later diverge per-instance (e.g. a distinct texture per building) via child-node property overrides without touching the blueprint scene | Easy — behavior-preserving; every fence/building transform value was carried over unchanged, verified headlessly before/after | fsamuels |
| D-9 | 2026-09-14 | Use a free CC0 rigged/animated horse model (Quaternius's Farm Animal Pack, via [poly.pizza](https://poly.pizza/m/F8HAAcLeBL)) for the first horse, ahead of the plan's own ordering (Phase 5 was meant to wait until the base environment was solid; the user asked for a real model with wander movement now) | Modeling/rigging/animating a horse from scratch is far more effort than this project's placeholder-first pattern justifies; Quaternius's pack is public domain (no attribution required, unlike CC-BY), already rigged with Idle/Walk/Run/etc. animations, and ships as glTF — no format conversion needed for Godot | Easy — a single `.glb` file plus one wrapper scene (`horse.tscn`) and one script (`horse.gd`); swappable for a different or higher-fidelity model later without touching the wander logic | fsamuels |
